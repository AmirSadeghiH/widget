# ویجت پشتیبانی — ۱۱ تم مستقل

نسخهٔ **7.0.0**: رابط فارسی/RTL، حالت روشن و تاریک، ورودی چندخطی، پاسخ جریانی و اتصال به پشتیبان انسانی. فایل‌های نصب آماده و مستقل‌اند؛ برای استفاده از ویجت به Node، Python یا بارگذاری فونت از CDN نیاز نیست.

## تم‌ها

| تم | فایل نصب | امضای طراحی |
|---|---|---|
| Classic | `widget/widget.js` | میز پشتیبانی؛ هدر گرادیانی، سلسله‌مراتب واضح، کارت‌های منظم |
| Onyx | `widget/widget-onyx.js` | کنسول دقیق؛ زوایای کنترل‌شده، خطوط ظریف و تایپوگرافی فنی |
| Linen | `widget/widget-linen.js` | تحریریه؛ ریل کنار متن، حاشیهٔ کاغذی، پیشنهادهای شماره‌دار و خط دوبل |
| Clay | `widget/widget-clay.js` | ارگانیک؛ انحناهای نرم و کنترل‌های حجیم و صمیمی |
| Atomic | `widget/widget-atomic.js` | مهندسی؛ ساختار ماژولار، شماره‌گذاری و خطوط هندسی |
| Fluen | `widget/widget-fluen.js` | خلاق؛ هدر شناور، گرادیان و ریتم متفاوت کارت‌ها |
| Glassmo | `widget/widget-glassmo.js` | شیشهٔ مات؛ لایه‌بندی شفاف با سطح خوانای متن |
| Material 3 | `widget/widget-md3.js` | سطوح tonal و ورودی و دکمه‌های کپسولی |
| Minimal | `widget/widget-minimal.js` | بدون قاب‌های اضافی؛ خطوط ساده، فضای تنفس و تمرکز روی متن |
| Neu | `widget/widget-neu.js` | حجم‌پردازی؛ سایه‌های دوگانه و ورودی فرورفته |

`widget.js` در ریشه، دقیقاً همان فایل Classic است. **فقط یکی** از فایل‌های نصب را در هر صفحه بارگذاری کنید؛ تغییر تم در استودیو با سند مستقل انجام می‌شود.

## نصب

```html
<meta name="viewport" content="width=device-width, initial-scale=1">

<script>
  window.AI_WIDGET_CONFIG = {
    title: "پشتیبانی آنلاین فروشگاه",
    subtitle: "راهنمای خرید و پیگیری سفارش‌های شما",
    greeting: "سلام! چطور می‌توانیم کمکتان کنیم؟",
    darkMode: "auto", // "light" یا "dark" نیز مجاز است
    suggestions: ["راهنمای خرید", "شرایط ارسال", "ساعات پاسخ‌گویی"],
    showTeaser: false
  };
</script>
<script
  src="/widget/widget-md3.js"
  data-api="https://YOUR_API_ORIGIN/api/chat/"
  data-widget-key="YOUR_PUBLIC_WIDGET_KEY"
  defer></script>
```

- نشانی API و **کلید عمومی نصب** را با مقادیر پروژه جایگزین کنید؛ توکن یا کلید خصوصی سرور را در صفحه نگذارید.
- API نمونهٔ استودیو برای تولید نیست. مسیرها و payloadهای گفتگو، تاریخچه، feedback، leads و handoff با قرارداد قبلی حفظ شده‌اند.
- endpoint معمولی با `/chat/` تمام می‌شود؛ مسیرهای هم‌خانواده از آن ساخته می‌شوند. برای مسیرهای غیرمتعارف، endpointهای مربوطه را صریحاً تنظیم کنید.
- متن‌های عنوان و توضیح، plain text هستند؛ شکسته‌شدن خطوط طبیعی است و به‌جای ellipsis، متن کامل حفظ می‌شود.
- میکروفون، ضبط صدا و speech recognition از همهٔ تم‌ها حذف شده‌اند. تنظیم قدیمی `enableVoiceInput` دیگر کنترل صوتی ایجاد نمی‌کند.
- فونت Vazirmatn در خود فایل JS قرار دارد. برای CSP، بارگذاری script، سبک‌های دارای nonce و فونت `data:` را در سیاست سایت بررسی کنید. nonce تگ script به سبک‌های ویجت منتقل می‌شود.
- رنگ‌های سفارشی در صورت نیاز برای خوانایی اصلاح می‌شوند؛ مقدار نمایشی لزوماً همان hex ورودی نیست.

## رفتار ورودی و دسترس‌پذیری

- دسکتاپ: **Enter** برای ارسال و **Shift+Enter** برای خط جدید.
- ورودی touch: Enter خط جدید می‌سازد؛ دکمهٔ ارسال همیشه در دسترس است. Ctrl/Command+Enter نیز ارسال می‌کند.
- تأیید یا لغو IME باعث ارسال ناخواسته یا بسته‌شدن گفتگو نمی‌شود.
- ارتفاع ورودی محدود و خودکار است؛ پیش‌نویس پیام بعدی در حین پاسخ باقی می‌ماند. دکمهٔ ارسال هنگام دریافت پاسخ به **توقف** تبدیل می‌شود.
- حالت‌های انتظار، آفلاین، سرویس ناموجود، محدودیت سرویس و پشتیبان انسانی جدا هستند؛ توضیح مشتری برای نمایش وضعیت بازنویسی نمی‌شود.
- کنترل‌های اصلی touch حداقل ۴۴ پیکسل‌اند. فرم و تأیید حذف گفتگو، مدیریت فوکوس، Escape و محتوای زمینهٔ inert دارند.
- فرم تماس با Enter ارسال می‌شود؛ دادهٔ در حال ارسال قابل ویرایش نیست و در خطا، داده و امکان تلاش دوباره حفظ می‌شود. بستن فرم در اسکرول نیز قابل دسترسی است.

## استودیوی طراحی

نیاز ابزار توسعه: **Node 22+، npm 10+ و Python 3.10+**.

```sh
npm ci
npm run preview
```

سپس `http://localhost:4173` را باز کنید. سرور روی `0.0.0.0` است و در Arena از پنل **Live Preview** نیز باز می‌شود.

- `widget/_themes_gallery.html`: انتخاب ۱۱ تم، روشن/تاریک، عرض واقعی iframe، مقایسهٔ همه، رنگ برند و سناریوهای تعاملی.
- `widget/_design_check.html`: نمایش مستقل یک تم؛ پارامترهای `theme`، `mode`، `act` و `primary` را می‌پذیرد.
- `widget/_themes_check.html`: بررسی سریع هر ۲۲ حالت بعد از آماده‌شدن ویجت و فونت‌ها.

استودیو به `/demo-api/` محلی متصل است و پاسخ‌های آزمایشی تولید می‌کند. حالت preview به تاریخچه و تنظیمات ذخیره‌شدهٔ واقعی کاربر دست نمی‌زند. این سرور حافظه‌ای/آزمایشی را روی محیط production منتشر نکنید.

## توسعه بدون اختلاف بین تم‌ها

**فایل‌های تولیدشدهٔ `widget*.js` را مستقیم ویرایش نکنید.** منابع اصلی:

| منبع | کاربرد |
|---|---|
| `scripts/widget-runtime.js` | رفتار مشترک، composer، درخواست‌ها، تاریخچه و فرم‌ها |
| `widget/design-core.css` | ساختار responsive و دسترس‌پذیری مشترک |
| `widget/ui-shell.js` | وضعیت، توضیح، draft و placeholder |
| `widget/live-handoff.js` | SSE/polling و چرخهٔ پشتیبانی انسانی |
| `widget/themes/*.css` | ساختار و هویت هر تم |
| `widget/themes/manifest.json` | پالت‌ها و پیش‌فرض‌های ۱۱ تم |

```sh
npm run build      # تولید هر ۱۱ فایل و alias ریشه، با UTF-8 و LF ثابت
npm run check      # کنترل هماهنگی خروجی‌ها و تست‌های منبع
npm test           # کنترل منبع + تمام تست‌های مرورگر
```

Chromium لینوکس و کتابخانه‌های لازم از npm تأمین می‌شوند؛ دانلود جداگانهٔ Playwright browser لازم نیست. روی سیستم‌های دیگر می‌توانید `WIDGET_BROWSER_PATH` را به مرورگر Chromium نصب‌شده تنظیم کنید.

تست‌ها با API محلیِ قراردادمحور اجرا می‌شوند. نتیجه و حدود بررسی را در [QA.md](QA.md) ببینید. بررسی Safari/Firefox، کیبورد واقعی iOS/Android و API تولید بخشی از تأیید نهایی انتشار روی محیط شماست.
